# M5: native Bridge, scoped Files and optional acceleration

Historical design. The current [shared environment/control specification](https://github.com/kb5000/trames-runtime/blob/main/docs/architecture/environment-configuration.md)
replaces the single device and guest command shown below with capability-scoped
`/dev/trames/*` nodes and `trames rpc DEVICE METHOD JSON_PARAMS`.

Version 0.3.0/build 4 adds a versioned asynchronous guest device, a native consent
broker, persistent Files directory authorizations and a measured optional C++
integer interpreter. The reference Rust backend remains the default. These are
statically compiled app capabilities; there is no downloaded native plugin loader.

## Guest protocol and native authority

A local environment exposes `/dev/trames-bridge` as a 0600 character device.
It accepts newline-delimited JSON, including fragmented/coalesced writes:

```json
{"version":1,"id":1,"method":"device.info","params":{}}
```

The guest receives either `{"version":1,"id":1,"result":...}` or an `error`
object containing `code` and `message`. Request IDs are unsigned 64-bit values.
`/usr/local/bin/trames` provides `trames info` and `trames bridge 'JSON'`.
Open descriptions and protocol state are shared by dup/fork. Seeking and
positioned IO return ESPIPE. Native tickets are scoped to their session handle;
responses cannot be sent through the guest syscall interface.

| Method | Parameters / result |
| --- | --- |
| bridge.info | Pure protocol/capability metadata |
| clipboard.read | `{}`; returns bounded text |
| clipboard.write | `{text}`; at most 16 KiB UTF-8 |
| url.open | `{url}`; HTTP/HTTPS only, without embedded credentials |
| device.info | `{}`; platform, system version and device model |
| files.list | `{}`; opaque grant IDs, display names and export permission |
| files.import / files.export | `{grant,path,guest}`; relative provider path, absolute guest file path |
| request.cancel | `{id}`; cancels a pending request on the same open description |
| accel.list | Built-in registry ABI/version, enabled state and metrics |
| accel.enable / accel.disable | `{id:"sha256"}`; pure native SHA-256 availability |
| accel.sha256 | `{text}`; at most 16 KiB UTF-8, lowercase hex digest |

M5 required a visible **allow once** decision for every clipboard, URL,
device-information or Files request. Starting with the 0.18.0/build 21 test app,
text clipboard reads/writes execute automatically, as requested by the owner;
iPadOS controls the paste permission prompt for reads, and writes have no OS
permission dialog. URL, device-information and Files requests retain the visible
**allow once** decision. Denial performs no native operation. Guest root is not
host permission. The settings switch rejects all new native requests when disabled.
Pure protocol metadata and hashing do not access native resources. Unrecognized
methods/parameters and unsupported URLs fail explicitly. Native failures omit
provider paths and private system error details.

Limits: 32 KiB guest frames/replies, 64 KiB output per connection, 16 connections,
32 pending native requests per session and eight per connection. Consent expires
after 120 seconds. Expired/cancelled/closed requests reject late replies; expiry
removes authority even if a slow guest has filled its output queue. Write/read
backpressure is explicit; native effects are never automatically retried.

Embedding ABI version 2 adds nonblocking poll/reply/active operations and a
backend-availability query. Worker-owned VFS/runtime state remains on its worker;
only integer handles and bounded caller-owned C buffers cross the Swift boundary.

## Persistent Files authorizations

Settings lets the user select at most 32 directories through Files. Authorizations
are import-only by default; export is an explicit option. Native bookmarks are
stored privately and refreshed when stale. The guest sees an opaque UUID, not
bookmark bytes or the native root path. Files requests still require per-request
consent, including requests using an existing grant.

Relative paths reject absolute components, dot/dot-dot, NUL, overlong components
and symbolic links. Validation runs again inside NSFileCoordinator's accessor.
Security scope stays alive through the coordinated native copy and streamed VFS
transfer, and is released on success/failure/cancellation. Copies use 64 KiB
buffers and a 1 GiB per-file limit; growing sources also obey the streaming limit.
Exports create new files exclusively. Existing destination files are preserved.
Revocation cancels active transfer tickets and prevents subsequent work.

These operations are copies. File-provider POSIX mounts, general host paths,
recursive directory copying, overwrite, notifications and Share Sheet RPC remain
outside this implementation. Provider behavior and bookmark persistence require
physical iPad acceptance in addition to macOS/simulator checks.

## Interpreter and accelerator registry

The following executor description records M5/0.3 behavior. The optional C++
engine and its selectors are removed in the current source; see
[ADR-003](../decisions/ADR-003-static-native-compute.md). The Bridge accelerator
registry remains available. The future [Trames Accelerator RFC](accelerator.md)
proposes ABI-compatible guest library stubs and a separate native-call transport;
the historic SHA-256 Bridge registry does not implement that mechanism.

`--features cpp` statically compiles `native/interpreter-cpp`; the CLI selects it
with `--backend cpp` (or the trusted `TRAMES_BACKEND` environment variable).
The iPad app includes the backend and exposes an experimental switch for the next
local session. `--metrics` reports instruction count and runtime on stderr.

The C++ ABI 1 uses checked POD integer state and a contiguous executable block
of at most 64 words. Calls execute at most 4,096 instructions. A bounded cache
holds at most 256 blocks. Computed-goto dispatch validates indices; a portable
switch build implements the same transitions. No guest memory address becomes a
native pointer. Rust performs memory, SIMD, floating point, syscall and fault
handling. Unsupported words return before effects. Dense fallback blocks use
Rust for the rest of the slice. No JIT or instruction fusion is enabled.

Instruction-cache invalidation tracks mappings/protection and writes to guest
executable pages. Ordinary data writes still advance the global revision used by
exclusive monitors but do not invalidate cached instruction blocks. Thread-shared
address spaces share both revisions; ordinary fork snapshots remain private.

The built-in accelerator registry has ABI version 1, SHA-256 and bounded metrics
(calls, bytes, elapsed nanoseconds, unavailable fallbacks). It starts disabled;
callers enable it explicitly and can fall back to the guest's `sha256sum`.
The registry is not libc interposition or a binary native-plugin SDK. Additional
accelerators need their own bounded ABI, implementation, license review and
correctness/performance evidence.

## Storage reset and DNS

Guest `/usr` is writable. Private inode objects now open host files only while
performing IO; closed guest files do not retain native file descriptors. This
fixes descriptor exhaustion being reported as EIO on file creation/reopen.
Native EMFILE/ENFILE are now reported as their Linux errno values.
New stores have a 16 GiB logical budget and 131,072 inode/path entries.

The owner elected to reset development data rather than retain unused historical
compatibility. Only manifest format v3 is accepted; v1/v2 conversion and exact
old-default quota/resolver migrations are removed. Current-format stores retain
normal persistence and configured limits. Unsupported metadata is rejected
without deletion; deletion requires the native explicit reset operation.

Settings > Reset Linux closes the local session, waits for its store lock and
then removes that private environment. Initial installations carry a generation
check so a cancelled download cannot later promote stale data. SSH configuration
and Files authorizations are outside the Linux store. Reset is a background
operation, not guest RPC, and cannot delete a live store.

First-install downloads use an ephemeral URLSession that waits for connectivity
on Apple platforms. Transient offline/DNS/connection/timeout errors receive at
most three download attempts with 0.5/1 second backoff. Cancellation stops the
sequence; HTTP/archive validation errors fail directly. Installation and native
Bridge effects are not retried. The app shows preparation while waiting for
network authorization, then starts Alpine after the verified download completes.

`10.0.0.1` and `fd00::1` are the virtual gateway DNS addresses; the guest address
is `10.0.0.2`. The gateway answers internal names and resolves external A/AAAA
through the host system resolver. The owner reported DNS lookup failure on iPad;
Linux and Apple simulator real-name resolution/HTTPS apk tests pass, so the
physical-device failure is not established as a wrong resolver address. Explicit user DNS edits remain unchanged on reopen. A temporary
public-resolver configuration can bypass the gateway while diagnosing the device.
