## 前后产物及缓存校验

证据根目录为 `target/validation-fuse-performance-20261125`。基线从上一轮写回实现前的快照重建，261 个初始 Rust 文件指纹全部匹配。两份独立源码共 1179 个文件，差异仅为 FUSE 写回批次的 12 个生产／测试路径，见 `baseline-source.json`、`candidate-source.json`、`source-delta.json`；没有回退或改动实时工作区的其他实现。

两份产物使用相同的 `rustc 1.101.0-nightly (4ebd25825 2026-10-15)`、锁文件和 release 配置（thin LTO、overflow checks、debug=0、incremental=0、jobs=1），并嵌入相同已验证 guest CLI。冻结产物为：

- 基线：`trames-run-baseline`，SHA-256 `38a2dedd6f02a3fb8a18fa311515543c96030a6ec54b21db773fbbae3a898704`。
- 候选：`trames-run-candidate`，SHA-256 `8ec534e87462d4ab38c50beb9049fd7280c1bea81dcdf4c03e5caba7d679197d`。

首次候选构建被 Cargo 缓存误复用为基线，产物指纹相同，已在正式采样前拒绝。原因是两个源码目录使用同一个私有 target，而恢复的基线源文件 mtime 更新，候选复制的旧 mtime 没有使相关缓存失效。只清理本轮私有目录中的 VFS release 缓存后重建候选，并重新验证产物指纹和实际能力协商。被拒绝产物、日志和原因保留在 `candidate-cache-reuse*`，没有进入结果。

基线构建 255.958 秒，最终候选重新编译 181.739 秒。正式样本在两者终止后开始；前后产物哈希不同，能力预检也分别确认“未激活／实际激活 writeback”。源码和工具指纹见 `runners.json`、`measurement-inputs.json`、`used-fixtures`。本轮没有提交、推送或更新配对 pin。

## 测量方法与范围

新普通 Linux 客户端为 `runtime/tests/fixtures/fuse-performance.c`，不实现 FUSE 协议。相同静态 ARM64 ELF 先做原生功能预检，再在本轮构建结束后记录正式原生对照，最后用于解释器前后对照。

- 原版 libfuse 3.14.0 低层、writeback、高层三配置，解释器各 1／2／4 CPU。guest 普通负载并行进程数等于该次 CPU 配置。
- 每组采用 AB、BA 两个块，每个进程启动后预热一次，再计时两次；每个产物／配置／CPU 有四次正式传输样本。普通负载每个产物／CPU 跨三配置有 12 次正式工作组，统计最慢 worker 的中位耗时。
- 正式样本使用 daemon `-f -s`，关闭调试跟踪；单独的 `-d` 诊断只用于核对请求尺寸和协商，不进入性能统计。启动、导入和卸载耗时单独记录，不能除文件字节数当作吞吐。
- 客户端使用正确的 `CLOCK_MONOTONIC` 秒×1e9＋纳秒换算。8 MiB 文件用 64 KiB 块写入，分别计写入、fsync、打开状态下读取、关闭后重新打开读取；读入验证固定字节模式、总长度和 EOF。其余偏移／取消／资源身份语义复用独立功能回归，固定重复模式的吞吐探针不能单独证明块重排不存在。
- 普通负载为确定性整数计算、1000 次 stat/open/close、512 轮定位文件读写及 512 轮 pipe 读写，数据均校验。native 与 guest 的计算校验和一致。

正式解释器阶段 421.422 秒，38 个进程范围、364 条客户端记录全部完整：含 72 条正式传输样本、168 条正式普通 worker 样本，另有预热及能力诊断。没有失败、超时、中止或磁盘停止。正式原生三配置有 36 条客户端记录，位于 `target/local-ci/io/fuse-performance-20261125/native-final`；构建期间的第一次原生运行只作功能预检，其计时未进入正式结果。

这是同一 Mac 上两个解释器 release 的对照。Linux VM 原生对照保存独立环境和原始值；没有把跨环境的比例当作运行时回归结论。全程复用现有共享 VM，没有重启或变更其他任务。

## 下一整批实现输入

以下问题在同一 FUSE 领域集中处理，包含调用方、退化分支和生命周期，全部完成后再统一验证。现有数据证明性能退化；各路径的单独因果占比尚未通过修改后反证确认。

1. **冷读合并**：独立协议诊断中，基线为 256 次 64 KiB READ，候选为 2048 次 4 KiB READ。候选写后读取没有 daemon READ，重新打开后的读取按页拆分。需合并连续冷页请求，同时保留每个接受页、原 caller／FH、失败、短读零值和通知／取消语义。
2. **消除重复缓存拷贝**：`File::operation` 已生成缓存命中输出，随后仍进入 buffered Io 再读取页面，并在 `FileResult::finish` 再做 overlay；缓存写入后也再次执行 `cache.written`。需复用已接受结果，避免重复内存写入和多次脏代次更新，不改变允许的 guest 竞态结果。
3. **回写批量与时间更新**：目前每次非同步缓存写完成都提交 background，回写期间持原 inode 写事务，数据后还传时间。需在已有 worker 上批量积累／回写，避免每小写进入完整排队；同步写、close、sync_file_range、截断、错误序列及 executor 退出仍须完整兑现。
4. **布局准入**：`SyncResource::layout` 当前无条件提供 inode 布局，即使没有映射也走 HostFileTask 的布局调度。评估无映射时的直接路径，并保留映射开始／结束竞态和确有共享映射时的对象准入，不能以一次 `mapped()` 观测取代生命周期证明。
5. **原资源维护**：普通缓存写新增频繁 OpenWriter，弱 writer 注册在新建时只追加，主要在查询时清理。批次需避免失效 weak 条目随写次数积累，同时不创建文件／缓存自持有循环，不增加算法级锁或协调／服务线程。
6. **一次统一验证**：增强吞吐客户端的每块序号，修复整批后统一验证 Apple／Linux FUSE、原版工具与匹配 release 对照，复用未受影响的通过证据。此阶段不重新触发未变的完整 CPU／网络／图形矩阵；正式集成仍需最终 HVF、物理 iPad、完整 CI 和配对提交推送。
