# FUSE 有界快照与回复接续复验（2026-11-25）

承接[上一轮优化检查点](fuse-optimization-20261125.md)：前候选写入＋同步 8 MiB 为 70–77 毫秒。此次先完成快照、回复、未发送页、时间回传和原写引用的整批实现，再集中验证。功能通过，写入＋同步降至 24–29 毫秒，但同轮基线为 17–18 毫秒，仍多 32%–68%；两 CPU 追加对照仍多约 41%。**性能门槛继续未通过**，02 FUSE 与 01–12 总目标保持开放。

## 本批实现

1. 一次原布局准入复制最多 1 MiB 连续脏数据，快照上限与连接 WRITE 上限分离；每条消息仍遵守原连接上限，包括 8193 字节等非页对齐上限。原 inode 写事务、页身份、脏代次、FH／OFD、同步范围和 EOF 均保留。
2. 合法中间 ACK 只推进已拥有的私有快照游标，直接发送剩余字节，不修改共享页、inode 或映射。最终 ACK、重新取数据、失败及清脏仍回到原布局准入，不能以 mapped() 的一次观察代替排他租约。
3. 分片失败只退役已被请求触及的页；快照中从未发送的页回到原脏页队列并重新取得准入。前段成功后发生 ENOSPC、零长度短回复或畸形回复，都继续写其余原脏页并保留首个错误；后续 mmap 写入的脏代次不被旧 ACK 清除。
4. 压力触发的普通缓存数据回写与时间回传分开。close、fsync、同步写、syncfs 和显式映射关闭仍使用完整屏障；sync_file_range 只处理选定页及等待语义。原后台布尔标志改为现有 inode 队列中的弱原任务引用，关闭回退可以把排队或正在运行的数据任务升级为时间屏障，终态采样与移除任务使用同一队列锁，避免丢掉迟到的关闭请求。
5. OpenWriter 复用原可写 FH／OFD 的 mount 租约；普通写入自身的 readonly 准入仍保留。缓存写的权限准备只保留必要头部和自己的输入，不提前复制一份不会发送的 WRITE 数据报文。原权限检查、capability／setid 清除、direct I/O 和错误顺序保留。
6. 收尾审计发现取消发生在请求已发布、句柄尚未回填的窗口时，旧终态未清 pending，可能重新持有已退出任务的请求。现于终态清除此标志，复用原安装条件撤回迟到句柄。回归通过连接的实际就绪通知在发布当下取消，不使用测试线程或时间等待。

所有生产执行仍使用现有 guest worker、SyncExecutor 和执行池；没有新协调／资源服务线程、轮询总线、算法全局锁或普通访存屏障。共享改动只使用既有平台接口，Apple 专用路径继续沿用 target cfg；Mac 与 Linux 同时验证。

Linux 依据：[FUSE 回写和 write_inode／close](https://github.com/torvalds/linux/blob/v6.12/fs/fuse/file.c)、[FUSE 时间回传](https://github.com/torvalds/linux/blob/v6.12/fs/fuse/dir.c)。时间回传与数据请求合并不是同一协议义务；完整同步屏障仍须兑现。

## 下一整批实现输入

先取得成本拆分，再完成同一 FUSE 批次的已知处理、调用方和退化分支，最后统一验证；不凭 worker 数或请求数断言耗时原因。

1. 用独立诊断区分实际快照／帧分配／字节复制、入池与唤醒、必要布局等待及 guest 执行的成本。诊断与正式计时分开，保留相同产物／原始样本，不往生产路径新增常驻测量或服务线程。
2. 评估在回复所在现有 worker 上，用原布局写票据直接尝试取得排他租约，推进有界的已接受续接；确有读者时仍回原执行池。不能使用一次 mapped() 观察跳过准入，不能让真实阻塞占住 guest 槽，完成回调和下一任务的分发应在释放该租约后进行。
3. 检查冷读回复已经拥有完整数据时，是否还必须从刚发布的缓存帧再复制一次输出，以及完整页初始化是否重复清零。若复用已接受输出，应保留每页发布结果／原 caller／OFD 和范围；新脏页、短读零值、截断／增长、通知、分组混合及取消路径继续使用正确的原缓存或快照，不能为少复制返回过期的页内容。
4. 所有快路径都包含发布当下退出、重复／畸形回复、分片失败和未发送页、迟到元数据升级、FD 复用及映射写入代次；不让退出回填请求，也不增加确定性竞争获胜顺序。
5. 整批完成后统一跑受影响的两宿主库／实际调用方、原版工具、gVisor 及同配置 release 对照。复用未受影响的通过证据；完整领域审计和最终平台／交付门槛继续保留。
