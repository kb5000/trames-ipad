# FUSE 原布局内续接与冷读输出复用（2026-11-25）

承接[有界快照批次](fuse-writeback-batch-20261125.md)，本批先完成回复准入、冷读输出、完整页初始化和相关取消／失败分支，再集中验证。功能验证通过；写回 8 MiB 的写入＋同步仍比同轮基线多 30%–48%，性能门槛未通过。02 FUSE 与 01–12 总目标保持开放。

## 实现与原资源边界

- 最终 WRITE ACK、时间回传和 FSYNC 回复在原 worker 上尝试原 inode 的 LayoutWrite 排他租约；取得后推进有界状态，释放租约后才分发请求或完成回调。有实际读者时，仍把同一个已接受任务交回原 SyncExecutor；中间 ACK 继续只推进私有快照。没有以 mapped() 的一次观察代替排他准入。
- 冷读的完整原 READ 回复在每个原页均成功发布、没有采用更新脏页或 EOF 裁剪、且原请求所有成员仍保留时，可以一次性移动到输出；单页结果仍保留，其他跟随者继续可读。混合分组、缺少成员、更新脏页、EOF 裁剪和再次消费均回退到原页结果。
- 完整覆盖的冷页只在准备阶段预约原缓存额度；收到所有边缘页后才提交初始化。原实现会在边缘 READ 尚未完成时把中间完整页提前公布为可读零页，取消或边缘错误后可能保留错误缓存。本批延后公布，并直接用输入初始化尚未分配的页；已有物理页保留身份。
- 使用现有 inode 事务、对象锁、页代次、OFD／FH、调用者和执行器；没有新增协调／服务线程、轮询总线、全局算法锁或普通访存屏障。
- 共享实现使用既有平台无关接口；Apple 特定类型、API、依赖和链接继续沿用现有 target cfg。本批同时检查 Apple 与 Linux 的库及实际共享调用组合。

新增 7 个回归函数覆盖跨页取消／边缘读取错误、中间页缓存、完整短读输出一次性消费和跟随者、新脏页获胜、EOF 缩小后再增长、空闲时内联完成，以及持有原布局读者时的原执行器回退。完成回调另检查原内联租约已经释放。

## 复核发现与下一批边界

后续[有界失败与事件批次](fuse-bounded-failures-20261125.md)已修复并验证下述同步失败续接风险；同批另修正实际验证发现的定时器／协议发布空窗。本页保留原检查点产物和性能数据，不作为最新组合的验收结论。

代码复核发现一条尚需补强的错误接续：`Wave::dispatch` 同步收不到连接请求时直接调用 receiver；当前 receiver 会在能取得布局租约时内联处理失败、捕获后续脏页并再次 dispatch。如果连接持续同步拒绝，剩余大量脏数据可能形成连续递归。这是代码路径推断，尚未作为实际崩溃复现或已修复项。下一批应将该同步失败与其他已知问题一起处理，保留原错误、未发送页、代次与 inode 队列语义，把原任务交回既有执行器，不增加线程；使用原连接的确定性断开验证每次有界接续和最终收尾。此项解决前不提交本候选或关闭 FUSE。

同一批继续拆分成功写入的帧分配／初始化、缓存预约、快照／报文复制和原执行器成本，针对同配置基线剩余约 5–8 毫秒的差距实施全部已知可推进路径，再统一验证。已有非空调用栈仅定位候选路径，不能证明它们各自占用多少耗时；不因修改记录或等待方式重跑全部矩阵。
