# FUSE 写回优化与集中复验（2026-11-25）

承接 [release 性能检查点](fuse-performance-20261125.md)。前一候选在原版 libfuse writeback 配置下写入并同步 8 MiB 需 0.86–1.09 秒。本批先实现所有已知优化及生命周期分支，再集中验证：功能通过，读取已接近同轮基线，写入＋同步降至 70–77 毫秒，但仍为同轮基线的 3.06–4.05 倍，**性能门槛仍未通过**。02 FUSE 与 01–12 总目标保持开放。

## 实现范围

- 冷页读取按连续范围合并，遵守原连接单次数据上限。每页保留原 OFD、FH、身份、缓存代次与等待结果；最后一个使用者取消请求，单页使用者退出不取消其余页的请求。短回复按页补零，失败保留给已接受的等待者。
- 缓存命中复用已接受的输出，普通缓存写入不重复复制或再次标脏。通知失效期间的非映射输出使用自己的完成快照，不回填已失效的映射代次；映射故障仍按原规则重新验证。
- 小写按保守的脏页压力积累到最多 1 MiB 后交给现有执行器；close、同步写、fsync、范围同步、映射关闭和错误传播保留原语义。弱写入引用及时清理，执行器退出不能把未排空的数据伪装成成功 FLUSH。
- 布局空闲时用原 LayoutWrite 取得相同的排他租约，直接交给现有执行池；真实映射读者仍走原就绪／静止准入，不使用 mapped() 的竞态观察跳过准入。旧退出测试补上实际读者占用，分别覆盖已准入与尚待准入的生命周期。
- Linux 原生对照表明，可写 OFD 尚存时普通只读重挂载返回 EBUSY。FUSE OPEN 原先只在打开过程中持有 mount 写入引用，现将同一引用转给原 FH／OFD 的完整生命周期。只读打开及 O_PATH 不持有写引用；拒绝重挂载后仍能同步，最后关闭后可切只读，并拒绝新的写打开。

没有新增协调／资源服务线程、轮询总线、算法全局锁或普通访存屏障。共享实现未引入 Apple 专用 API／类型／依赖／链接项，复用现有平台接口及 target cfg；同时编译检查 Apple 和 Linux 路径。

行为依据：[Linux v6.12 mount 写引用与只读准入](https://github.com/torvalds/linux/blob/v6.12/fs/namespace.c)。原生失败及错误预期的客户端均保留，未用绕过 readonly 检查的路径实现该行为。

## 下一整批实现输入

继续只处理 FUSE，先完成以下写回状态机、调用方和退化路径，再统一验证，不按单个优化重复完整矩阵。以下是协议及源码支持的候选原因，尚未确定各项的耗时占比。

1. **分离快照与线上的 WRITE 上限**：当前积累到 1 MiB，但快照仍以单次线上的 128 KiB 为界，且每条回复都重新提交现有执行池。评估在一次原布局准入下形成有上限的连续快照，再按原连接上限发送；不以 mapped() 的一次观察绕过布局排他。
2. **回复仅推进已拥有字节**：有效的中间 ACK 若仅更改私有快照游标、继续发送已复制字节，可避免无实际页变更时的重复准入；清脏、通知后失效、最终完成、真实错误及重取数据仍回到原对象／布局准入。不得让取消或退出保留资源自持有循环。
3. **完整失败与范围语义**：扩大快照前先定义已发送／未发送页的处理，不能因前一分片失败清掉从未发送的脏页。包含非法／短回复、非页对齐连接上限、部分范围同步、稀疏页、截断、新 mmap 写入代次、close／FD 复用、executor 退出及原错误序列；保留正常 guest 竞态。
4. **写入引用与时间回传**：已有原可写 FH／OFD 的 mount 引用，评估复用其租约以减少每次小写重复的引用维护；另核对数据批次与时间回传是否必须同批。Linux 在 inode 回写等路径处理时间，不能仅为减少请求就漏掉 close、fsync、同步写和属性权威。[Linux v6.12 FUSE 回写实现](https://github.com/torvalds/linux/blob/v6.12/fs/fuse/file.c)
5. **集中验收**：实现整个已知批次后重跑受影响的两端库／调用方、原版工具及相同 release 对照，复用未受影响的通过结果。仍使用现有 worker／执行池，不增加协调或资源服务线程。
