# FUSE 失败续接、映射计数与事件生产者复验（2026-11-25）

承接[内联回复检查点](fuse-inline-replies-20261125.md)。本批先实现有界失败续接、原映射生命周期计数、快照与报文分配，再集中验证。过程中实际发现定时器到期与信号发布之间的调度空窗，连同同型协议回调一起修正后重新验证。功能通过；写回成本仍需继续处理，02 与 03–12 总队列不关闭。

## 实现

1. **失败回复返回原任务。** 成功的中间 ACK 继续发送原有私有字节，成功的终段仍可持原布局租约内联续接；错误回复则将同一个已接受任务交回原 SyncExecutor。断开的连接持续同步拒绝请求时，不再递归处理整个脏文件。原页代次、首个任务错误、未发送页、inode 队列和请求取消规则保留。执行器退出仍使用原失败收尾。
2. **映射观察为常数成本。** 原 Mapping 创建和最终 Drop 配对维护 inode 缓存中的一个 Relaxed 原子计数；普通观察不再遍历全部缓存页。独立映射、VMA／View 的 Arc 克隆及失效通知继续使用原对象生命期，实际布局变更仍须原 Layout 准入。没有新增普通访存屏障。最初关于失效会漏计旧映射的推测已纠正：现有失效路径保留仍有映射的页，没有该项现存正确性缺陷的证据。
3. **一次分配有界快照。** 在原布局租约下先确定连续页、代次和 EOF，再为最多 1 MiB 的准确范围一次分配和复制；小写入不预留整整 1 MiB。WRITE 报文为头部加该分片数据一次预留容量。协议上限、非页对齐分片、部分失败、范围同步及后续 mmap 脏代次不变。
4. **事件消费到发布仍是活跃生产者。** 调度执行器在释放队列锁执行 `Timers::tick` 和 `HostProtocols::progress` 前，增加既有 `q.completing`，回到原队列后减少。截止时间从索引移除后、信号或就绪尚未入队之前，另一执行器不能将这段工作误判为死锁。继续使用既有执行器、对象锁和条件等待，没有协调／服务线程或轮询。

平台共用接口保持不变；Apple 专用类型、API、依赖和链接继续沿用已有 target cfg。两宿主的 VFS／syscall 和 Session 全部目标严格检查均通过。

### 实际 splice 异常与调度修正

第一冻结产物 `8af5cfff…55086` 的原始整组为 **410 通过、10 跳过、1 无结果**：`SpliceTest.ToPipeWithSmallCapacityDoesNotSpin` 未输出 XML，进程返回 125，stderr 为“all virtual processes are blocked without an event source”。原始 chunk、拆分重试和 stderr 全部保留。

该用例在同一产物和上一产物的单例复核中都通过；新旧完整 splice 组随后十轮重复也都通过，因而不把这些重跑单独当作修复因果证明。固定上游[原测试源码](https://github.com/google/gvisor/blob/89cacadae21eca4270a8f7c79281d0426d33ac5f/test/syscalls/linux/splice.cc)表明它创建单调时钟 POSIX 定时器，一秒后向原线程发信号，预期阻塞 splice 返回 EINTR。该观察与代码中的事件消费／信号发布空窗吻合。

两个新增确定性回归直接进入实际定时器信号回调和协议 progress 回调，在原截止时间已经消费、回调尚未返回的窗口获取原队列并尝试终态判定。新保护使该判定被拒绝；回调完成后计数恢复。测试不用延时、轮询或新测试线程。移除测试未用导入后两项再验通过；另一次补验使用了错误的目标拼写，在执行测试前即退出，随后使用实际 `kernel-conformance` 名称运行，不能把该次配置错误记成通过。

复核 `take_with_engine` 的全部 12 处显式释放队列锁：10 处实际生产者回调由完成计数保护，宿主事件等待由原 `host_waiting` 标志保护，原生服务观察由锁内二次空闲／probe 判定保护。此结论针对该调度循环，不等于所有等待实现均已完成全局审计。

最终 `bd748d96…b82ed` 产物重新跑完整受影响 gVisor 集合，原始整组全过；没有 CPU 前提替换或失败结果覆盖。原始无结果和新旧重复成功同时保留，不据此声明所有可能的死锁均已消除。

## 下一批输入与交付边界

- 对同步阶段按原任务拆分“尚未处理的写入、原布局等待、执行器交接、回复与 FSYNC”的成本；不要仅从请求数、线程数或当前缓存帧热点推断耗时。诊断单独运行，禁止生产路径常驻采样或增加协调线程。
- 检查压力触发写回在原执行器实际启动与后续 fsync 排队期间的任务、数据和 inode 事务生命周期；完成同批所有可推进调用方与回退后再统一验证，保持原 caller／OFD／FH、页代次、范围、EOF 和错误顺序。
- 对照固定内核源码和原生握手确定写回 inode 事务必须覆盖的范围，包括与后续普通缓存写、truncate／属性修改、关闭和同步屏障的关系；先验证实际等待边界，再决定修改。不能提前确认尚未完成的 WRITE／元数据／FSYNC，也不能通过关闭协商缓存规避开销。
- 完整 FUSE 领域审计、正常负载控制、HVF／物理 iPad、最终 CI 与配对交付仍保留；不因本轮整组通过而关闭 02，不新增 SSHFS／rclone 支持声明。03–12 按原顺序。
